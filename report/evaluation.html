For my dash app, because I'm using the free render plan, response times are slow, both when filtering the data and especially when the page loads. I often have to wait up to a minute, then reload the page, before the interactive chart displays. There is a simple fix for this, in future I would use a more capable, paid hosting service.

I considered implementing something similar to FPL Data, where the user can select any two statistics to graph against each other. On the other hand, I think this can be very confusing to the user, as there are no explanations of the significance of each graph, like I have on my information system. I ultimately settled on having only 5 charts, but allowing the user to choose to only display players from certain teams or who play in certain positions.

Another potential future development would be expanding the recommendation system, by using betting odds, then calculating implied probabilities of an event. There is a basic implementation of this in captaincy_calculator.py. It requires the user to search online for odds of a player scoring a certain number of goals, then enter them into the terminal after running the code. It then calculates the expected value of FPL points earned from scoring goals. A better implementation of this would use betting odds from an API, but these are all paid and so I didn’t use them in this project. This improved program would ideally be hosted externally and accessed in a browser. It could predict the players with the highest expected value of FPL points in that week, by using betting odds for goals, assists, cards, clean sheets etc. I have not found an implementation of this online, so it would be a novel approach. I found sites that state the calculated probabilities of these events, but don’t apply them in the way I discuss.
